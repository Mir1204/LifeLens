# LifeLens Machine-Learning Models

This document describes the three risk models used by LifeLens: their data sources, features, targets, estimators, evaluation results, and the values returned to the Flutter mobile app.

## Overview

| Model | Data source | Target | Output |
|---|---|---|---|
| Static stress | Kaggle Sleep Health & Lifestyle dataset | `stress_risk` | `Low`, `Medium`, `High` |
| Burnout trend | Synthetic longitudinal data | `burnout_risk` | `Low`, `Medium`, `High` |
| Overspending | Real income and expenses dataset | `overspending_risk` plus `overspending_score` | Label plus score from 0 to 100 |

All three are classification models. MSE is not the primary evaluation metric. Accuracy, balanced accuracy, precision, recall, and F1-score are used instead.

## 1. Static Stress Model

### Data

- Source: `backend/app/model_data/Sleep_health_and_lifestyle_dataset.csv`
- Preprocessed dataset: `backend/app/ml/data/static_stress_data.csv`
- Dataset size: 374 rows
- Preprocessing script: `backend/app/ml/training/preprocess_kaggle_data.py`

The source Stress Level value from 1 to 10 is converted to a categorical target:

| Source Stress Level | `stress_risk` |
|---|---|
| 1-4 | `Low` |
| 5-6 | `Medium` |
| 7-10 | `High` |

### Features

The model uses these six features:

- `sleep_hours_today`
- `sleep_quality_today`
- `steps_today`
- `physical_activity_today`
- `workload_proxy_today`
- `sleep_decline_proxy`

The application derives some of these values because the mobile payload does not directly contain all Kaggle fields. For example, sleep duration is converted into a sleep-quality proxy, steps are converted into an activity proxy, and workload is mapped to a 1-5 scale.

### Model

The training script compares:

- Logistic Regression
- Random Forest
- Histogram Gradient Boosting

The best model is saved to:

```text
backend/app/ml/artifacts/static_stress_model.joblib
```

The current saved artifact is a scikit-learn pipeline using the selected best estimator.

### Evaluation

Evaluation uses an untouched test partition after splitting the source data. The training partition is balanced separately.

- Test samples: 75
- Accuracy: 92.00%
- Balanced accuracy: 91.43%

### Runtime role

The static stress model is combined with the burnout trend model by `predict_burnout_risk()`:

- Static model contribution: 40%
- Burnout trend model contribution: 60%

It contributes to the final numerical `stress_risk` score and the categorical `burnout_risk` label returned to the app.

## 2. Burnout Trend Model

### Data

- Source: synthetic longitudinal data generated by `backend/app/ml/training/generate_synthetic_data.py`
- Dataset: `backend/app/ml/data/burnout_data.csv`
- Dataset size: 2,250 rows
- Simulation size: 150 users over 21 days, with prediction rows created after at least 7 days of history

The synthetic source is used because a suitable public dataset with the same daily sleep, screen-time, workload, and task-history fields was not available. Its target is a proxy for burnout risk, not a clinical burnout diagnosis.

### Features

The model uses these eight rolling features:

- `sleep_hours_avg_3d`
- `sleep_hours_avg_7d`
- `sleep_trend_7d`
- `screen_time_avg_3d`
- `screen_time_avg_7d`
- `screen_time_trend_7d`
- `workload_avg_7d`
- `high_priority_tasks_today`

### Target

The synthetic generator creates `burnout_risk` from a rule-based signal count:

- Low sleep average
- Declining sleep trend
- High screen-time average
- High workload average
- At least two high-priority tasks

The resulting target values are:

```text
Low
Medium
High
```

The generator also includes a small amount of random label noise. Therefore, the model accuracy should not be interpreted as real-world clinical accuracy.

### Model

The training script compares Logistic Regression and XGBoost. The current saved artifact is:

```text
backend/app/ml/artifacts/burnout_model.joblib
```

It uses the shared `LabeledXGB` wrapper so XGBoost predictions return string labels instead of encoded integers.

### Evaluation

- Test samples: 450
- Accuracy: 98.89%
- Balanced accuracy: 99.23%

These results measure performance against the synthetic proxy target. They mainly show that the model learned the generator's rules.

## 3. Overspending Model

### Data

- Source: `backend/app/model_data/data.csv`
- Dataset size: 20,000 rows
- Training script: `backend/app/ml/training/train_overspend_model.py`
- The old synthetic `overspend_data.csv` is no longer the training source.

The real dataset contains income and monthly expense categories such as rent, loans, groceries, transport, eating out, entertainment, utilities, healthcare, education, and miscellaneous spending.

### Derived features

The training utility creates:

```text
monthly_spending = sum of all monthly expense columns
expense_ratio = monthly_spending / Income
```

### Target columns

The original real dataset does not provide an overspending label, so the training pipeline derives two target columns:

```text
overspending_score
overspending_risk
```

The score is calculated as:

```text
score = clamp(((expense_ratio - 0.5) / 0.5) * 100, 0, 100)
```

The categorical target is assigned as:

| Score | `overspending_risk` |
|---|---|
| 0-39 | `Low` |
| 40-69 | `Medium` |
| 70-100 | `High` |

This is an explainable income-relative financial-risk target, not a human-labelled ground-truth target.

### Model features

The model is trained with:

- `Income`
- `monthly_spending`
- `expense_ratio`

### Model

The current estimator is `HistGradientBoostingClassifier`.

The saved artifact is:

```text
backend/app/ml/artifacts/overspend_model.joblib
```

### Runtime feature mapping

The app sends daily spending and the backend builds a 7-day rolling average. When monthly income is available, the prediction service estimates monthly spending as:

```text
estimated_monthly_spending = spending_avg_7d * 30
```

It then calculates the same `expense_ratio` used during training.

If the user has not entered monthly income, the service uses the previous ratio-based fallback and does not call the income-trained model.

### Evaluation

- Test samples: 4,000
- Accuracy: 100.00%
- Balanced accuracy: 100.00%

This perfect score is expected because the target is deterministically derived from `expense_ratio`, which is also a model feature. It demonstrates consistency with the target rule, but it is not evidence of real-world predictive accuracy.

## API Output Sent To Flutter

The backend endpoint is:

```text
POST /predict/daily-score
```

The response is defined by `ScoreResponse` and contains:

```json
{
  "productivity": 0,
  "financial_health": 0,
  "stress_risk": 0,
  "burnout_risk": "Low",
  "overspending_score": 0,
  "overspending_risk": "Low",
  "recommendations": []
}
```

Field meanings:

| Field | Type | Source |
|---|---|---|
| `productivity` | Integer, 0-100 | Rule-based scoring |
| `financial_health` | Integer, 0-100 | Rule-based budget scoring |
| `stress_risk` | Integer, 0-100 | Static stress and burnout model ensemble |
| `burnout_risk` | String | Burnout trend classification/ensemble |
| `overspending_score` | Integer, 0-100 | Income-relative expense ratio |
| `overspending_risk` | String | Overspending classification |
| `recommendations` | List of strings | Rule-based recommendations |

Flutter parses these values in `lib/models/lifestyle_scores.dart`. The dashboard displays the overspending result as:

```text
<score>/100 - <Low|Medium|High>
```

## Training and Evaluation Commands

Run from the `backend` folder.

Train the overspending model:

```powershell
python -m app.ml.training.train_overspend_model
```

Train the static stress model:

```powershell
python -m app.ml.training.train_static_stress_model
```

Train the burnout model:

```powershell
python -m app.ml.training.train_burnout_model
```

Evaluate all three models:

```powershell
python -m app.ml.training.evaluation
```

After replacing an artifact, restart the backend. Models are cached in memory and are loaded again when the backend process starts or when the model is first requested.

## Limitations

- Static stress uses a public sleep-health dataset with proxy feature mappings.
- Burnout uses synthetic data and a proxy target rather than labelled clinical burnout data.
- Overspending uses a real financial dataset, but its target is derived from income and expenses.
- The overspending score estimates monthly spending from a 7-day app history window.
- Model accuracy does not guarantee medical, psychological, or financial advice quality.
